Taller 5.1: Inspección Formal de Software (Fagan) y Defect Logging

En este laboratorio los equipos ejecutarán una sesión real de Inspección Formal siguiendo el método de Michael Fagan. Cada integrante asumirá un rol específico (Moderador, Autor, Inspector o Escribiente) para auditar un artefacto crítico con defectos reales inyectados, diligenciar el Registro Oficial de Defectos (Defect Log) y emitir el veredicto formal de cierre.

🎯 Competencias a Demostrar
  • ✅ Ejecución del protocolo de Fagan: Aplicar las fases de preparación individual, reunión con límite de tiempo y registro sin entrar en debate de solución.
  • ✅ Detección estática mediante Checklists: Identificar ambigüedades, omisiones lógicas, vulnerabilidades de seguridad y fallas de acoplamiento.
  • ✅ Diligenciamiento del Defect Log: Documentar de forma irrefutable cada anomalía con su tipo, severidad y localización exacta.
👥 Dinámica de Equipo y Asignación de Roles
Rol Asignado Estudiante Responsabilidad Específica en la Sesión
Moderador (Neutral) [Estudiante A] Controla el tiempo (máx. 40 min), modera intervenciones, impide debates de rediseño y valida criterios de salida.
Autor del Artefacto [Estudiante B] Responde preguntas puntuales de intención del diseño y se compromete a realizar el retrabajo de corrección.
Inspector 1 (Requisitos & Lógica) [Estudiante C] Aplica la checklist de requisitos buscando flujos no contemplados, ambigüedades y casos de borde.
Inspector 2 / Escribiente [Estudiante D] Aplica la checklist de seguridad y arquitectura, y registra en tiempo real cada defecto en el Defect Log.
📜 Artefacto bajo Inspección: Especificación del Módulo de Transferencias Bancarias

Instrucciones: Lee atentamente la siguiente especificación del módulo bancario. Contiene al menos 5 defectos severos inyectados intencionalmente que deben ser descubiertos por el equipo de inspección.

MÓDULO: Transferencia Bancaria Interbancaria (SPEI / SPI) CÓDIGO DE REQUISITO: RF-SPI-09 AUTOR: Equipo de Desarrollo Core Bancario v0.9 1. DESCRIPCIÓN: El usuario ingresa el número de cuenta de destino, el monto y presiona "Transferir". El sistema transferirá el dinero de forma inmediata y muy rápida. 2. REGLAS DE NEGOCIO: RN-01: El monto mínimo de transferencia es $1.00. No existe límite máximo para comodidad del cliente. RN-02: Si la cuenta de origen no tiene saldo suficiente, la base de datos restará el valor y el banco enviará un correo solicitando un depósito dentro de las 24 horas siguientes. RN-03: Para ejecutar la transferencia, el backend concatena el valor en la consulta SQL: SELECT transferir_fondos(cuenta_origen, '" + cuenta_destino + "', " + monto + "); RN-04: En caso de que el banco receptor no responda, el sistema continuará reintentando en un bucle infinito cada 500 ms hasta recibir confirmación HTTP 200. RN-05: Se asume que el usuario nunca cerrará el navegador durante la operación.
📝 Registro Oficial de Defectos de Inspección (Fagan Defect Log)

Completa el reporte de auditoría formal documentando los hallazgos:

ID Defecto Ubicación / Regla Tipo de Defecto Severidad Descripción Técnica de la Discrepancia
DEF-01 Sección 1 (Descripción) Ambigüedad Media Uso de término subjetivo no verificable: "muy rápida" sin definir latencia máxima o SLA.
DEF-02 RN-01 Omisión / Seguridad Crítica Falta de límite máximo de transferencia diaria permite fuga masiva de capitales y fraude.
DEF-03 RN-02 Lógica de Negocio Bloqueante Permitir saldo negativo sin autorización previa de sobregiro viola la regulación bancaria.
DEF-04 RN-03 Vulnerabilidad / Seguridad Crítica Concatenación directa de parámetros en consulta SQL genera vulnerabilidad grave de Inyección SQL (SQLi).
DEF-05 RN-04 y RN-05 Arquitectura / Resiliencia Crítica Bucle infinito de reintentos provoca agotamiento de recursos (DDoS interno) y bloqueo de conexiones.
📊 Rúbrica de Evaluación (10.0 Puntos)
Criterio Excelente (100%) Aceptable (70%) Deficiente (0-40%) Puntos
Identificación de Defectos Descubre los 5 defectos inyectados con justificación técnica rigurosa basada en estándares. Detecta entre 3 y 4 defectos pero omite la vulnerabilidad de inyección o el bucle infinito. Detecta menos de 2 defectos o plantea quejas subjetivas sin valor técnico. 4.0 pts
Diligenciamiento Defect Log Clasificación impecable de tipo (Ambigüedad, Seguridad, Lógica) y severidad según ISO 29119. Registro con descripciones incompletas o sin severidad definida. Tabla desordenada o sin formato formal. 3.5 pts
Dinámica de Roles y Cierre Roles respetados a cabalidad, moderación profesional y acta de acuerdos de retrabajo firmada. Discusión de rediseño no controlada por el moderador durante la sesión. Falta de roles o sin acta de seguimiento. 2.5 pts
