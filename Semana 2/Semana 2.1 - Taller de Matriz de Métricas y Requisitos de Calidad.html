Taller 2.1: Especificación y Matriz de Métricas de Calidad ISO 25010

En este taller estructurarás el documento de especificación formal de requisitos de software y diseñarás la matriz de métricas de calidad que gobernará el Proyecto Integrador, asegurando que cada atributo de calidad (bajo el modelo clásico de 8 características de ISO 25010:2011 o el modelo actualizado de 9 características de ISO 25010:2023) cuente con una fórmula matemática objetiva (ISO 25023), un umbral de aceptación verificable y una técnica de prueba asociada.

💡 Flexibilidad de Estándares en el Proyecto Integrador:
Puedes estructurar tu matriz utilizando el modelo clásico ISO/IEC 25010:2011 (8 características del sílabo) o incorporar las innovaciones de la revisión ISO/IEC 25010:2023 (9 características, destacando Seguridad Operacional / Safety para proyectos con impacto en personas/bienes, Capacidad de Interacción y Flexibilidad). Ambos enfoques son válidos y reconocidos.
🎯 Competencias a Desarrollar
  • ✅ Especificar requisitos no funcionales: Redactar requisitos de calidad sin ambigüedades, asociándolos a las características de ISO 25010 (versión 2011 u 2023).
  • ✅ Construir la Matriz de Métricas: Definir indicadores cuantitativos formales (ISO 25023) con umbrales booleanos (pasa / no pasa).
  • ✅ Alinear criterios de aceptación: Establecer los criterios de parada y aceptación contractual del Proyecto Integrador.
📝 Actividad 1: Formulación de Requisitos de Calidad en Formato EARS / Planguage

Los requisitos de calidad deben formularse utilizando el estándar de Tom Gilb (Planguage) para garantizar verificabilidad absoluta:

# Ejemplo 1: Seguridad de la Información (Security - ISO 25010:2011/2023) Etiqueta: RNF-SEG-01 (Seguridad - Autenticación) Descripción: El sistema debe proteger las sesiones de usuario frente a ataques de fuerza bruta. Escala: Número de intentos fallidos consecutivos permitidos por dirección IP y por cuenta. Métrica: Intentos_Fallidos_Consecutivos Meta: Bloquear temporalmente la IP tras 5 intentos fallidos en una ventana de 15 minutos. Peor caso aceptable: Bloquear tras 7 intentos. Método de Medición: Simulación de ataque mediante script automatizado de pruebas de penetración (DAST). # Ejemplo 2: Seguridad Operacional / Inocuidad (Safety - Novedad ISO 25010:2023) Etiqueta: RNF-SAF-01 (Seguridad Operacional - Fail-Safe) Descripción: En caso de desbordamiento en la telemetría del sensor médico, el actuador de infusión debe entrar en modo de parada segura sin suministrar dosis erróneas. Escala: Tiempo de detección y transición al estado seguro tras la anomalía. Métrica: Latencia_Transicion_FailSafe (ms) Meta: < 50 ms hacia estado bloqueado sin sobredosis. Peor caso aceptable: < 100 ms. Método de Medición: Inyección intencional de fallos de hardware/software en banco de pruebas (Fault Injection Testing).
📐 Actividad 2: Construcción de la Matriz de Métricas de Calidad

Los equipos de proyecto deben completar la siguiente matriz institucional para al menos 5 características distintas de la norma ISO/IEC 25010 aplicadas a su solución:

ID Característica ISO 25010 Nombre de la Métrica Fórmula Matemática (ISO 25023) Umbral de Aceptación Método de Verificación
M-01 Eficiencia de Desempeño Latencia Media P95 Avg(ResponseTime) en P95 ≤ 350 ms bajo 200 usuarios concurrentes Prueba de Carga con Apache JMeter
M-02 Seguridad (Security) Vulnerabilidades Críticas OWASP Count(CVEs con CVSS ≥ 7.0) 0 vulnerabilidades en branch main Análisis Estático (SAST) con SonarQube
M-03 Seguridad Operacional (Safety - 2023) Tiempo de Entrada en Estado Seguro Tiempo_Detección + Tiempo_Rollback ≤ 200 ms ante fallo crítico de hardware/API Pruebas de Inyección de Fallas (Chaos Engineering)
M-04 Mantenibilidad Cobertura de Código (Coverage) (Líneas Ejecutadas / Líneas Totales) * 100 ≥ 80% en lógica de negocio del backend Pruebas Unitarias automatizadas (JUnit/pytest)
M-05 Fiabilidad Tasa de Falla en Transacciones (Peticiones HTTP 5xx / Total Peticiones) * 100 < 0.05% en pruebas de esfuerzo Monitoreo de logs y métricas APM
M-06 Usabilidad / Capacidad de Interacción Eficacia de Accesibilidad Web Violaciones WCAG 2.1 Nivel AA 0 violaciones críticas de contraste o ARIA Auditoría automatizada con Axe / Lighthouse
📊 Rúbrica de Evaluación (10.0 Puntos)
Criterio Excelente (100%) Aceptable (70%) Deficiente (0-40%) Puntos
Especificación de Requisitos Redacción en estándar Planguage/EARS, completamente cuantitativa y sin ambigüedades. Requisitos con redacción entendible pero con métricas parcialmente subjetivas. Requisitos vagos ("que sea rápido") no verificables. 3.5 pts
Matriz de Métricas ISO 25010 Cubre al menos 5 dimensiones con fórmulas matemáticas válidas y umbrales técnicos coherentes. Matriz incompleta (menos de 4 características) o fórmulas matemáticas erróneas. No utiliza la taxonomía ISO 25010. 4.0 pts
Método de Verificación Asocia herramientas y métodos de prueba viables y modernos (JMeter, SonarQube, UAT). Métodos de prueba genéricos sin especificar instrumentación. No especifica cómo se medirá la métrica. 2.5 pts
