Taller 3.1: Análisis Causa-Raíz, Pareto y Configuración de SCM

En este laboratorio aplicarás las herramientas estadísticas para diagnosticar la causa raíz de un incidente crítico en un sistema de producción, priorizarás los focos de defectos mediante Pareto y configurarás las políticas de control de configuración (SCM) en GitHub con branch protection, tagging semántico de líneas base y plantillas de pull request.

🎯 Competencias a Demostrar
  • ✅ Análisis de Causa Raíz: Diseñar un diagrama de Ishikawa completo con al menos 12 causas secundarias clasificadas en las 6 categorías de software.
  • ✅ Construcción de Pareto: Tabular un dataset de 150 defectos de software, calculando frecuencias acumuladas y marcando el corte 80/20.
  • ✅ Gestión de Configuración en Git: Establecer una línea base congelada mediante Git Tag (SemVer) y documentar los ítems de configuración (SCI).
🐟 Tarea 1: Diagrama de Causa-Efecto (Ishikawa)

Escenario del Incidente: En el sistema de matrículas universitarias, durante los primeros 10 minutos de apertura, el 65% de los estudiantes experimentaron caídas de sesión (HTTP 504 Gateway Timeout), perdiendo los cupos seleccionados.

Construye el diagrama de espina de pescado clasificando causas en:

Problema Central: "Caída de sesión y timeout masivo en matrículas bajo alta concurrencia" 1. Personas: (Ej. Falta de capacitación en arquitectura de microservicios, desarrollador junior sin supervisión en consultas SQL). 2. Procesos: (Ej. No se ejecutaron pruebas de estrés pre-apertura, no hubo plan de rollback). 3. Entorno: (Ej. Pool de conexiones de base de datos insuficiente: max_connections = 50). 4. Requisitos: (Ej. No se especificó el requisito de usuarios concurrentes en la historia de usuario). 5. Código / BD: (Ej. Consultas N+1 en el ORM sin índices en tabla 'matricula_estudiante'). 6. Pruebas: (Ej. Solo se probaron flujos unitarios con 1 usuario simulado).

🛡️ Tarea 3: Implementación Práctica de SCM en GitHub

Ejecuta en tu repositorio del Proyecto Integrador la congelación de la Functional Baseline v0.1.0 mediante comandos Git:

# 1. Crear y taggear la línea base funcional (Baseline) git checkout main git tag -a v0.1.0-baseline.functional -m "Línea Base Funcional Aprobada: Requisitos y Arquitectura Inicial" git push origin v0.1.0-baseline.functional # 2. Configurar el archivo .github/pull_request_template.md con checklist de calidad # Incluir en el PR template: # [ ] Casos de prueba unitaria agregados y pasando # [ ] Análisis de linter / SonarQube sin violaciones críticas # [ ] Requisito trazable con ID en la matriz RTM
